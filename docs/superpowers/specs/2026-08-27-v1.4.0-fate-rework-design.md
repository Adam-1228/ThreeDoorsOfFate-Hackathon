# Three Doors of Fate v1.4.0 — 운명 재구성 설계

작성일: 2026-08-27
대상 브랜치: `codex/v1.4.0-fate-rework`
기준 버전: `v1.3.0` (`7bd1646`)
상태: 사용자 설계 검토 대기

## 1. 목적

`1.4.0`은 카드 수치만 조정하는 패치가 아니다. 모바일에서 런을 안전하게
이어 갈 수 있게 하고, 직업별 시작 덱의 정체성을 고정하며, 적과 이벤트의
반복을 줄이고, 무한 모드와 런 기록에 장기 목표를 부여하는 대형 패치다.

패치의 작업명은 **운명 재구성**이다.

핵심 목표는 다음과 같다.

1. 모든 난이도에서 문 선택과 카드 확인이 공정하고 복구 가능해야 한다.
2. 시작 덱의 운이 아니라 직업과 계약 선택이 초반 전략을 결정해야 한다.
3. 기존 적 20종이 서로 다른 전투 판단을 요구해야 한다.
4. 한 런 안에서 이벤트와 무한 모드의 반복감을 줄여야 한다.
5. 이전에 반복됐던 프리뷰·프레임·레이어 회귀를 구조적으로 막아야 한다.
6. `1.3.0` 저장 데이터, 업적, Game Center ID와 수집 진행을 보존해야 한다.

## 2. 비목표

다음 항목은 `1.4.0`의 완료 조건이 아니다.

- 네 번째 직업이나 신규 지역 전체 추가
- 실시간 멀티플레이 또는 PvP
- Android 계정 및 크로스플랫폼 클라우드
- 서버 기반 사용자 행동 분석
- 한국어·영어 이외의 추가 언어
- 기존 72개 카드 전체의 일괄 수치 재조정
- 신규 Game Center 업적 추가
- 전체 게임 컨트롤러의 일괄 재작성
- 배너 광고, 강제 광고, 확률형 상품 또는 인앱 결제 추가
- 사용자가 제거를 요청했던 전투 효과음 복원

현재 Game Center 업적은 총 1,000점이므로 신규 목표는 로컬 런 기록으로
제공한다. 기존 업적의 점수나 영구 ID는 변경하지 않는다.

## 3. 현재 상태와 설계 근거

현재 구현에서 확인한 사실은 다음과 같다.

- 시작 덱은 30장이며 카테고리별 후보를 중복 허용 무작위 추출한다.
- 카드 에셋은 72개지만 시작 보상 한 장이 30장 덱에 미치는 영향은 작다.
- 일반 적 템플릿은 기본 10종, 어려움 추가 10종이지만 공용 행동 풀을
  대부분 공유한다.
- 일반 이벤트는 `ShowEvent`의 두 선택지 한 종류가 반복된다.
- 런 체크포인트는 어려움 또는 무한 모드에서만 사용할 수 있다.
- 상점 카드 본체를 누르면 즉시 구매되며 상세 프리뷰는 포인터 호버에
  의존한다.
- 무한 모드는 주로 적 능력치 배율과 보상 금화가 증가한다.
- `ThreeDoorsGameController.cs`는 12,129줄이며 화면 생성과 게임 규칙이
  한 클래스에 강하게 결합돼 있다.

따라서 콘텐츠만 추가하면 이전의 UI 겹침과 상호작용 회귀가 다시 발생할
가능성이 높다. `1.4.0`은 필요한 시스템만 순차 분리하면서 플레이 콘텐츠를
확장한다.

## 4. 전달 전략

같은 `1.4.0` 브랜치 안에서 다음 내부 마일스톤을 순서대로 완료한다.

1. **Foundation** — 고정 시드 난수, 데이터 계약, 체크포인트 v2,
   카드 검사 오버레이
2. **Run Identity** — 24장 시작 덱, 직업별 시작 계약, 카드 정리
3. **Encounter Variety** — 이벤트 카탈로그, 적 행동 프로필, 보스 단계
4. **Endless & Records** — 심연 변칙, 최근 런 기록, 로컬 코믹 기록
5. **Release Hardening** — 마이그레이션, 다중 화면 검증, 현지화,
   배포 메타데이터

마일스톤마다 회귀 테스트를 통과해야 다음 단계로 진행한다. 모든 기능을
한 번에 구현한 뒤 마지막에 고치는 방식은 사용하지 않는다.

## 5. 시작 덱과 운명 계약

### 5.1 결정적 시작 덱

각 직업은 무작위 30장 대신 명시적으로 정의된 24장 기본 덱을 사용한다.

- 공격 10장
- 방어 8장
- 특수 6장
- 직업 전용 카드 최소 4장
- 저주·희귀·어려움 전용 카드는 시작 덱에 포함하지 않음

이 구성은 현재 시작 손패의 공격 카드 등장 확률을 크게 낮추지 않으면서
보상 카드와 카드 제거의 영향력을 높인다. 시작 덱은 카드 ID와 수량이
데이터 파일에 기록되며 동일 계약과 동일 버전이면 항상 동일해야 한다.

### 5.2 직업별 시작 계약

직업마다 세 종류, 총 아홉 종류의 시작 계약을 제공한다.

각 계약은 다음 항목만 변경할 수 있다.

- 기본 덱에서 최대 네 장 교체
- 시작 금화 `-10`에서 `+10`
- 시작 체력 `-6`에서 `+6`
- 시작 행운 또는 빚 최대 1 변화

계약은 직업의 핵심 성향을 나눈다.

- 도박사: 고행운 폭발 / 금화와 판돈 / 재굴림 제어
- 예언가: 의도 대응 / 문 예언 / 행운 저장
- 추방자: 저체력 공격 / 빚 정화 / 방어와 반격

계약 선택 화면은 기존 직업 확인 화면 뒤, 런 시작 직전에 나타난다. 계약
본문에는 바뀌는 카드와 자원의 전후 값을 명시한다. 별도 그림은 필수가
아니며 기존 카드 그림과 프레임을 재사용할 수 있다.

### 5.3 카드 정리

휴식은 다음 세 선택지를 제공한다.

1. 체력 회복
2. 금화 획득
3. 카드 한 장 제거

상점은 방문당 한 번 카드 제거 서비스를 제공한다. 같은 런에서 제거할수록
가격이 상승한다. 제거 확인 화면에서 카드 전체 그림과 제거 후 덱 수를
표시한다.

안전 규칙은 다음과 같다.

- 덱이 12장 이하이면 제거 불가
- 공격 카드가 4장 이하가 되는 제거는 불가
- 선택과 최종 확인을 분리
- 제거 결과는 체크포인트와 런 기록에 저장

## 6. 카드 검사와 명시적 행동

카드 본체를 누르는 동작은 어느 화면에서도 즉시 구매·획득·사용을 실행하지
않는다. 모든 화면은 다음 흐름을 공유한다.

1. 카드 선택
2. 최상위 검사 오버레이 표시
3. `사용`, `구매`, `받기` 또는 `제거` 버튼으로 명시적 확정
4. 카드나 오버레이 바깥을 눌러 취소

적용 화면은 전투, 전투 보상, 상점, 보물, 이벤트 카드, 카드 제거다.

`CardInspectionOverlay`는 일반 HUD와 화면별 콘텐츠보다 높은 전용 레이어를
사용한다. 화면이 다시 그려져도 오버레이가 다른 프레임 뒤로 이동하지
않아야 하며, 한 번에 하나만 존재해야 한다. 호버는 데스크톱 편의 기능으로
남길 수 있지만 행동의 필수 경로가 되어서는 안 된다.

## 7. 체크포인트 v2

### 7.1 지원 범위

쉬움, 보통, 어려움, 무한 모드 모두 체크포인트를 지원한다. 자동 저장은
다음 안정 지점에서만 수행한다.

- 런 시작 계약 확정 후
- 문 선택지가 완성된 뒤
- 문 선택 확정 직후, 전투·상점·이벤트 해석 전
- 상점·보상·이벤트의 실제 제안이 확정된 직후
- 상점·보상·이벤트 선택이 끝나고 다음 문으로 돌아온 뒤
- 무한 모드 체크포인트 화면

전투 한가운데의 턴 상태는 저장하지 않는다. 앱이 전투 중 종료되면 같은
전투의 시작 상태로 복원하되 적, 보상, 문 선택을 새로 굴리지 않는다.

### 7.2 저장 데이터

체크포인트 v2는 기존 필드에 다음 항목을 추가한다.

- `runId`
- `runSeed`
- `randomCursor`
- 선택한 시작 계약 ID
- 카드 제거 횟수
- 이미 본 이벤트 ID
- 현재 심연 변칙 ID 목록
- 확정된 문 선택지 세 개
- 현재 또는 다음 전투의 적 ID와 전투 시드
- 확정된 상점·보상 제안 ID

복원 후 같은 선택지와 같은 결과 후보가 나타나야 한다. 강제 종료로 제안을
다시 굴리는 행위는 허용하지 않는다.

`SeededRunRandom`은 문, 적, 의도, 주사위, 카드 보상, 상점, 이벤트,
아이템 발견과 무한 변칙처럼 런 결과에 영향을 주는 모든 난수 경로에
사용한다. 화면 애니메이션과 장식 효과의 난수는 게임 난수와 분리한다.

### 7.3 호환성과 실패 처리

- 기존 `HardRunSaveVersion = 1` 저장은 한 번 읽어 v2로 변환한다.
- 알 수 없는 카드나 아이템 ID가 있으면 원본 저장을 즉시 삭제하지 않는다.
- 복원 실패 시 오류 이유를 기록하고 기존 로컬·iCloud 진행은 보존한다.
- 게임 오버 또는 정상 귀환 때 활성 체크포인트를 삭제한다.
- 업적, 발견 아이템, 장착 아이템과 난이도 해금 키는 변경하지 않는다.

오프라인 싱글 플레이이므로 강제 종료를 완전히 부정행위 방지 대상으로
취급하지 않는다. 목표는 결과 재굴림 방지와 모바일 런 손실 최소화다.

## 8. 이벤트 카탈로그

`1.4.0`은 최소 여덟 개 이벤트를 제공한다.

- 공용 이벤트 4개
- 도박사 전용 1개
- 예언가 전용 1개
- 추방자 전용 1개
- 빚 4 이상에서만 등장하는 계약 이벤트 1개

각 이벤트는 ID, 현지화 키, 등장 조건, 반복 정책, 두세 개 선택지와 결과를
데이터로 정의한다. 선택 결과가 사용할 수 있는 효과는 체력, 최대 체력,
금화, 빚, 카드 획득·제거, 문 정보, 아이템 발견이다.

같은 이벤트는 한 10문 구간에서 반복하지 않는다. 조건에 맞는 새 이벤트가
없을 때만 이미 본 공용 이벤트를 다시 허용한다. 선택 버튼은 적용 후 자원
상태를 미리 보여 준다.

모든 사용자 노출 문자열은 `game_text.json` 키로 제공하고 새 한국어 문자열을
컨트롤러에 직접 넣지 않는다.

## 9. 적 행동 프로필과 보스 단계

### 9.1 일반 적

기존 적 그림과 템플릿 20종을 유지하되 각 적에 행동 프로필을 연결한다.
최소 다섯 행동 성향을 제공한다.

- 공격형: 연속 공격과 취약
- 수비형: 방어 축적 후 강타
- 징수형: 빚과 빚 비례 피해
- 교란형: 행운·행동력·카드 흐름 압박
- 재생형: 회복을 막기 위한 타이밍 요구

모든 적은 공용 카드 외에 최소 두 개의 고유 행동을 가져야 한다. 이름과
능력치만 다른 적을 허용하지 않는다.

### 9.2 선택 공정성

- 쉬움·보통에서는 같은 의도를 세 턴 연속 선택하지 않음
- 쉬움에서는 직전 의도 반복 가중치 감소
- 보통에서는 현재 점수 기반 선택을 사용하되 즉사 가중치에 상한 적용
- 어려움과 무한에서는 적극적인 점수 선택 유지
- 모든 실제 피해는 표시된 최종 피해 계산을 그대로 사용

무작위 선택은 `runSeed` 기반 난수 소스를 사용한다. 테스트에서 동일 시드가
동일 의도열을 만들어야 한다.

### 9.3 엘리트와 보스

엘리트는 다음 중 하나의 변칙을 가진다.

- 고리대금: 빚 행동 강화
- 봉인: 특정 방어·특수 대응 요구
- 광폭: 낮은 체력에서 공격 행동 강화

보스는 체력 70%와 35%를 기준으로 최대 세 단계 행동 풀을 사용한다. 단계
전환은 공격 전에 화면과 진행 기록에 표시한다. 전환 턴에 숨겨진 즉시 피해는
발생하지 않는다.

## 10. 무한 모드의 심연 변칙

무한 모드에서는 다섯 문마다 세 개 후보 중 하나의 `심연 변칙`을 선택한다.
`1.4.0`은 최소 여섯 개 변칙을 제공한다.

변칙은 반드시 위험과 보상을 함께 가진다. 예시는 다음과 같다.

- 적 공격 강화 + 전투 금화 증가
- 적 방어 강화 + 희귀 카드 가중치 증가
- 휴식 회복 감소 + 카드 제거 비용 감소
- 빚 획득 증가 + 문 정보 한 단계 증가
- 상점 가격 증가 + 상점 제안 한 장 증가
- 시작 손패 제약 + 행동력 회복 선택 제공

동일 변칙은 중첩할 수 없으며 활성 변칙을 상태 확인과 체크포인트 화면에서
볼 수 있어야 한다. 단순 능력치 배율만 계속 올리는 방식은 사용하지 않는다.

## 11. 운명 기록

로컬에 최근 열 개 런을 저장한다. 이 기록은 Game Center 점수나 업적을
대체하지 않으며 iCloud 필수 데이터도 아니다.

각 기록은 다음 정보를 가진다.

- 런 ID, 버전, 날짜
- 직업, 난이도, 시작 계약
- 도달한 문과 격파한 전투·보스 수
- 귀환 또는 사망 원인
- 최종 체력, 금화, 빚
- 최종 덱 카드 ID와 장착 아이템 ID
- 선택한 심연 변칙
- 이번 런에서 달성한 업적
- 카드 사용 수, 받은 피해, 준 피해와 제거한 카드 수

메인 메뉴의 `운명 기록`에서 최근 런을 선택해 요약을 확인한다. 저장은 열 개를
초과하면 가장 오래된 항목부터 제거한다.

코믹한 목표는 Game Center 업적 대신 기록의 별칭으로 제공한다. 예를 들어
금화 없이 상점에 들어갔거나, 같은 재굴림 결과를 반복했거나, 높은 빚으로
귀환한 런에 별칭을 붙인다. 별칭은 점수와 보상을 제공하지 않는다.

## 12. 구조

전체 컨트롤러를 한 번에 교체하지 않는다. `1.4.0`에서 변경하는 규칙만
순수 C# 단위로 분리한다.

권장 구성은 다음과 같다.

```text
Assets/Scripts/Game/V140/
  SeededRunRandom.cs
  StarterContractCatalog.cs
  StarterDeckBuilder.cs
  EventCatalog.cs
  EncounterDirector.cs
  EndlessMutationCatalog.cs
  RunCheckpointV2.cs
  RunHistoryStore.cs

Assets/Scripts/UI/
  CardInspectionOverlay.cs

Assets/Resources/GameData/V140/
  starter_contracts.json
  events.json
  enemy_behaviors.json
  endless_mutations.json
```

원칙은 다음과 같다.

- 데이터 파싱과 규칙 검증은 Unity UI와 분리
- 난수는 인터페이스를 통해 주입
- 컨트롤러 partial은 화면 전환과 기존 시스템 연결만 담당
- 새 화면은 기존 프레임 자산을 재사용
- 고정 앵커가 필요한 경우에도 안전 영역과 공통 레이아웃 정책 사용
- 프리뷰, 설정, 업적, 아이템 상세는 공통 오버레이 계층 사용
- 새 데이터는 ID 중복, 누락 현지화와 잘못된 카드 참조를 시작 시 검증

## 13. 데이터 흐름

```text
직업 선택
  → 시작 계약 선택
  → 결정적 24장 덱 생성
  → runSeed 생성
  → 문 선택지 생성 및 체크포인트
  → 이벤트 또는 전투 디렉터
  → 명시적 보상·상점 선택
  → 다음 안정 지점 체크포인트
  → 보스/무한 변칙
  → 귀환 또는 사망
  → 최근 런 기록
```

같은 `runSeed`, 계약, 선택 이력은 동일한 제안과 적 후보를 만들어야 한다.
플레이어의 선택 결과까지 자동으로 고정하지는 않는다.

## 14. 오류 처리

- JSON 카탈로그 하나가 잘못됐다고 전체 게임을 시작 불가 상태로 만들지
  않는다. 오류 항목만 제외하고 명확한 검증 오류를 남긴다.
- 시작 덱 정의가 유효하지 않으면 기존 `v1.3.0` 시작 덱 생성기를 안전
  대체 경로로 사용한다.
- 이벤트 후보가 없으면 공용 안전 이벤트를 사용한다.
- 적 행동 프로필이 없으면 기존 공용 행동 풀을 사용한다.
- 체크포인트가 손상되면 메타 진행을 보존하고 해당 런만 복구 불가로 표시한다.
- 런 기록 저장 실패는 현재 런의 진행이나 게임 오버 화면을 막지 않는다.

대체 경로의 사용은 로그와 테스트에서 식별 가능해야 한다.

## 15. 검증 전략

### 15.1 순수 규칙 테스트

- 세 직업 × 세 계약이 각각 정확히 24장을 생성
- 기본 덱 카테고리가 10/8/6이고 불법 소스 카드가 없음
- 카드 제거 하한과 공격 카드 하한 검증
- 이벤트 ID·선택지·현지화·참조 카드 검증
- 적 20종 모두 고유 행동 두 개 이상 보유
- 동일 시드의 문·적·보상 결과 재현
- 쉬움·보통에서 같은 의도 세 턴 연속 금지
- 심연 변칙 중복 금지 및 위험·보상 쌍 검증
- 런 기록이 열 개를 넘으면 오래된 항목 제거

### 15.2 저장 마이그레이션 테스트

- v1 체크포인트를 v2로 변환
- v2 저장 왕복 후 덱, 자원, 아이템, 계약, 문 선택과 난수 위치 일치
- 알 수 없는 ID가 있어도 기존 메타 진행 보존
- 게임 오버와 정상 귀환에서 체크포인트 제거

### 15.3 상호작용 테스트

- 상점 카드 본체 한 번 클릭으로 구매되지 않음
- 카드 검사 후 명시적 버튼으로만 행동 수행
- 프리뷰 취소와 다른 카드 전환이 가능
- 모든 화면에서 프리뷰가 최상위 레이어에 표시
- 업적·설정·아이템 상세와 프리뷰가 동시에 중첩되지 않음

### 15.4 화면 검증

다음 화면비에서 문구와 프레임 침범이 없어야 한다.

- 16:9
- 19.5:9 iPhone 가로 화면
- 4:3 안전성 확인

검증 화면은 직업/계약 선택, 문 선택, 상태 확인, 전투, 상점, 보물,
이벤트, 업적, 게임 오버와 운명 기록이다.

### 15.5 기준선

작업 시작 기준선은 다음과 같다.

- Python 저장소 테스트 `116/116`
- 로컬 App Store 제출 자산 검증 통과
- 이전 `v1.3.0` Unity EditMode `299/299`

이 Mac에서는 별도 사용자의 명시적 허가 없이 Unity Editor, Unity CLI,
Xcode 또는 시뮬레이터를 실행하지 않는다. 코드와 데이터 준비 후 실제 Unity
검증이 필요하면 별도의 승인된 환경이나 새 명시적 허가를 사용한다.

## 16. 릴리스 조건

다음 조건을 모두 만족해야 `1.4.0` 제출 후보가 된다.

- 위 핵심 기능과 마이그레이션 테스트 통과
- 기존 20개 업적과 1,000점 Game Center 계약 유지
- `1.3.0` 저장 및 iCloud 진행 보존 확인
- 카드 구매·사용에 명시적 확인 경로 적용

  다시 승인
